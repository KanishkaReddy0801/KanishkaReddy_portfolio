01 — Overview

A Platform Built Around People

Bootlabs ATS is a purpose-built recruitment management platform designed to unify the hiring lifecycle across three distinct stakeholder groups — internal recruiting teams, job candidates, and external staffing vendors. The application was designed first in Figma, then developed into a fully functional React web application, with each user journey thoughtfully scoped into its own portal experience.

02 — Problem Statement

The Fragmented Hiring Experience

Recruitment at growing technology companies involves multiple parties — internal HR teams, candidates navigating a complex onboarding pipeline, and external vendors submitting profiles for open roles. Yet most ATS platforms are built with only one persona in mind: the recruiter. This creates a cascade of inefficiencies.

"How might we design a single, cohesive platform that empowers recruiting teams to manage the entire hiring funnel — while simultaneously giving candidates transparency over their journey and vendors the tools to submit and track profiles — all without introducing cognitive overload to any participant?"
Core Design Challenge — Bootlabs ATS
⚡
Operational Chaos
Recruiting teams juggle multiple disconnected tools — spreadsheets for tracking, email for communication, and manual follow-ups — leading to lost candidates and delayed hires.
🌀
Candidate Ambiguity
Candidates submit applications and then enter a "black hole" — no visibility into status, no self-service for documents, and no unified experience from offer to onboarding.
🔗
Vendor Disconnection
External staffing partners lack structured submission workflows, resulting in inconsistent candidate profiles, missed deadlines, and no performance feedback loop.

04 — Employee View

The Recruiter's Command Centre

The employee view is the core of the platform — a full-featured ATS dashboard accessible to internal Bootlabs recruitment staff via Google SSO authentication. It spans six major modules unified under a persistent dark sidebar navigation.

📊
Analytics Dashboard
Real-time hiring intelligence at a glance
Core Module

The dashboard opens with an immediate overview of recruitment health — KPI cards, hiring trend charts, pipeline distribution, and an activity feed — giving recruiters a situational awareness layer before diving into any specific task. Data is visualised using Recharts with area, bar, pie, and line chart types to match different data narratives.

Live KPI CardsTotal applications, active jobs, interviews this week, offer acceptance rate — all on load.
Hiring Trend ChartsMonthly applied → shortlisted → hired funnel visualised over a rolling 6-month window.
Source AttributionPie chart breakdown of candidate source channels — LinkedIn, referral, direct apply, job boards.
Aging Pipeline AlertsCandidates stuck at each stage flagged with colour-coded urgency indicators.
Recent Activity FeedTimestamped system events surfaced in a scannable card feed with contextual actions.
Top PerformersHiring managers and roles with highest close rates highlighted for pattern recognition.
💼
Jobs Management
Dual-view job listing with full CRUD operations
Core Module

The Jobs page offers a powerful table and card view toggle with animated transitions (Framer Motion), multi-criteria filtering, and inline editing. Recruiters can add single jobs or bulk-upload via CSV, edit job details, manage open/closed status, and deep-dive into each job's candidate pipeline through a rich detail dialog.

Table ↔ Card ToggleAnimated view switching via Motion library with spatial context preserved.
Advanced FiltersMulti-select filtering by department, location, status, salary band, and experience level.
Bulk CSV UploadPaste or upload CSV to create multiple job listings in one action with field mapping.
Job Detail DialogFull job spec sheet with candidate count, pipeline chart, and quick-action shortcuts.
👥
Candidates Module
Full pipeline lifecycle management per candidate
Core Module

Candidate management is the deepest module in the platform. Recruiters can view every candidate's full profile, move them through 7 pipeline stages, schedule interviews, add notes, edit details, and perform multi-select batch updates. A rich candidate detail dialog surfaces resume score, AI matching indicators, work history, and activity timeline.

7-Stage PipelineScreened → Interview Scheduled → L1 → L2 → Offer Extended → Hired → Rejected.
AI Resume ScoringCandidate-to-job match scores surfaced inline with skills gap analysis.
Multi-Edit ModeSelect multiple candidates and batch-update their status, assigned job, or stage.
Add CandidateStructured add dialog with all required fields and optional LinkedIn import prompt.
📅
Interviews & Settings
Scheduling, coordination, and platform configuration
Supporting Modules

The interviews module centralises all scheduled, completed, and upcoming interview events. Recruiters can schedule new interviews, select mode (in-person, video, phone), assign interviewers, and track outcomes per round. The settings module provides role management, notification preferences, integration toggles, and display customisation options.

05 — Candidate View

A Dignified Candidate Experience

The candidate portal is a self-contained experience accessed via a unique token-based link — no app download, no account creation required. It's designed for a single, emotionally significant moment: receiving and responding to a job offer.

The portal opens on the candidate's personalised offer letter — including position, department, full CTC breakdown with all components (base, HRA, allowances, bonus), joining date, reporting manager, and terms — presented in a format optimised for informed decision-making rather than legal jargon.
📄
Candidate Portal — Three Sections
Offer → Documents → Experience Survey
Candidate-Facing
📋
Offer Letter Review
The candidate sees a fully-structured offer with their name, role, CTC components, joining date, reporting manager, employment type, and probation period. Clear Accept and Decline CTAs with a confirmation dialog guard against accidental decisions. A rejection flow captures the reason — feeding back into recruiter analytics.
📁
Document Submission
After offer acceptance, candidates are unlocked into a document upload module listing all required pre-joining documents — Photo ID, Address Proof, Educational Certificates, Experience Letters, Relieving Letter, Salary Slips, and Bank Details. Each document shows upload status (required / uploaded / verified / rejected) with progress tracking and file validation.
💬
Experience Survey
A post-process feedback form capturing the candidate's interview experience — interviewer professionalism, communication quality, process transparency, and an open-ended comments field. The data feeds back into recruiter performance tracking and process improvement cycles.
06 — Vendor View

The vendor portal transforms how external staffing agencies interact with Bootlabs. Rather than operating through email chains and spreadsheets, vendors get a dedicated workspace where they can view assigned open roles, submit candidate profiles in a structured format, and track every submission's status in real time.

07 — Design System

A Coherent Visual Language

The application is built on a systematic design foundation using CSS custom properties, a shadcn/ui component library, and a consistent spatial rhythm — ensuring every surface from login screen to data chart feels part of the same designed system.

🎨 Colour System
  • Deep navy gradient sidebar (#0f1629 → #1a2240) establishes authority and focus
  • Blue 500 (#2D7FFF) as the single primary action colour for all CTAs and active states
  • Semantic colour tokens for 7 pipeline stages maintain scannable status at a glance
  • Light/dark mode support via CSS custom property overrides — no JavaScript required
  • Chart palette engineered for simultaneous legibility across 5+ data series
📐 Spatial System
  • 4px baseline grid for consistent vertical rhythm across all components
  • 10px border radius (--radius: 0.625rem) applied uniformly to cards, inputs, dialogs
  • Fixed 64px header and 256px sidebar create predictable content area geometry
  • Responsive breakpoints collapse sidebar at ≤1024px to prevent content crush
  • Generous whitespace in dialogs and cards reduces cognitive load for data-heavy views
⚙️ Component Architecture
  • shadcn/ui primitives (Dialog, Select, Tabs, Badge, Table) ensure accessible, ARIA-compliant interactions
  • Recharts library for all data visualisations — area, bar, line, pie chart types in use
  • Sonner (v2.0.3) for non-blocking toast notifications with action callbacks
  • Framer Motion (Motion library) for page transitions and view-toggle animations
  • Lucide React icons maintain a single, consistent icon language throughout
🔐 Authentication Design
  • Three distinct authentication flows — Google SSO (employee), token link (candidate), email entry (vendor)
  • Each portal has a tailored login screen reflecting its audience's mental model
  • State is persisted in localStorage with a clean logout flow that clears all session data
  • Animated login card with gradient background creates a premium first impression
  • Separate routing logic ensures portals cannot cross-contaminate sessions
08 — UX Principles

Design Decisions That Elevate the Experience

Six core UX principles guided every design decision in this application — from how data is organised to how feedback is communicated.

01
🎯
Context-Aware Navigation
Each portal has its own sidebar with role-relevant navigation items. A vendor never sees the recruiter's pipeline tools; a candidate never encounters vendor analytics. This reduces cognitive load and increases task confidence.
02
📊
Progressive Data Disclosure
Summary cards on the dashboard give high-level numbers. Clicking through opens detail dialogs with full data. This reduces information overload while keeping all details a single tap away.
03
💬
Immediate, Non-Blocking Feedback
Every action — adding a job, moving a candidate, accepting an offer — triggers a Sonner toast notification. Users always know their action succeeded without being blocked by a modal or page reload.
04
🔄
Animated State Transitions
View switches (table ↔ card), dialog opens, and sidebar active states all use smooth transitions. Motion cues communicate system state changes and keep users oriented in the interface hierarchy.
05
🛡️
Guarded Destructive Actions
High-consequence actions — rejecting a candidate, declining an offer, deleting a job — always require an AlertDialog confirmation step. This protects users from accidental irreversible decisions.
06
📱
Scalable Layout System
The fixed sidebar and scrollable content zone scale cleanly across screen sizes. Grid-based content areas accommodate dense data tables and sparse candidate cards within the same spatial framework.
This platform demonstrates that complex, multi-stakeholder enterprise tools can be designed with clarity, warmth, and genuine usability — when each user's journey is treated as a first-class design problem.
